模块由两个相互独立的 Cloud Functions 子包组成，各自拥有独立的 `package.json`、入口 `index.js`、`test/` 与依赖声明。

- `cloud/pickSpots/`：入口导出 `handler(event, context, deps)`，流程为 鉴权 → 校验候选体 → 通过 `PromptBuilder` 拼接提示词 → 调用上游 `LLM_CHAT_URL` → `guardPick` 守卫 ranked/note 字段长度与集合一致性 → 返回 JSON。
- `cloud/replanDay/`：入口结构同 pickSpots，额外实现 `normalizeRequest` 将 `{skippedId|addStopId|replaceStopId|intendText}` 归一化为单一 action，并计算 `remainingOf` 剩余待排站点；对 LLM 响应使用 `keep[] + freeBlocks[]` 语义模型而非有序数组。
- 共享模式：两个入口均实现相同的 `respond/fail/headerOf/parseBody` 小工具集，统一处理 Base64 body、UTF-8 字节上限、大小写不敏感 Header 读取。
- 可测试性：通过 `deps.fetch` 注入替身，`_test` 命名空间暴露内部验证器（如 `guardPick`、`normalizeRequest`、`remainingOf`）供单元测试直接调用。
- prompt 依赖隔离：pickSpots 的提示词来自同级 `prompt/ai/PromptBuilder.js`（由 bff/scripts/sync-prompt-contract.mjs 从 entry/SOT 同步），replanDay 无外部 prompt 依赖，保持零第三方库部署。
- 依赖方向：Cloud Function ← 本地模块（PromptBuilder、utils）→ 上游 LLM HTTP 端点；不直连数据库或业务服务。
