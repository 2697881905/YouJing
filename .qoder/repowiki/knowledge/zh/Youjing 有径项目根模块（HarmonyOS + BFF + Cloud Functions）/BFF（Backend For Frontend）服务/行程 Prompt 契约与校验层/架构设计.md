模块按职责拆为三个文件：
- `contract.js`：契约入口，通过 `createRequire` 加载 `generated/ai/TripSchema.js`，导出 `TRIP_JSON_SCHEMA`、解析后的 `TRIP_SCHEMA_OBJECT`、枚举表 `TRIP_ENUMS` 以及 `buildResponseFormat`（根据 `LLM_RESPONSE_FORMAT` 环境变量在 `json_schema` / `json_object` 间切换）。
- `index.js`：prompt 组装层，把 BFF 收到的请求体适配为 `PromptBuilder.userPrompt` 的参数；依据 payload 丰富度走两条路径——rich（含完整 `spots[]` + `area`）直接复用端侧 `PromptBuilder`，sparse（仅 `selectedSpots[]` + `selectedArea` 名称）则构造带「未提供」占位的文本提示，两者共享 `normalizeSpot` / `normalizeArea` 等归一化工具。
- `trip-validator.js`：基于 `TRIP_SCHEMA_OBJECT` 递归实现的 JSON Schema 验证器，外加业务语义约束（days 非空、startDate ≤ endDate、time < endTime、每天至少 lunch+dinner），作为 TripParser 之前的第三道防线。

`generated/` 子目录由 `bff/scripts/sync-prompt-contract.mjs` 从 `entry/src/main/ets/ai/{PromptBuilder,TripSchema}.ets` 同步生成，`package.json` 声明 `"type": "commonjs"` 以让 Node 以 CJS 方式加载 `.js` 文件；本模块对 `generated/` 单向依赖，不反向修改它。
