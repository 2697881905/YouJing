模块按职责拆为三个纯静态类文件：
- `WeatherStore.ets`：数据获取与双层缓存。先查进程内 `memory`（30 分钟 TTL），再读 `@kit.ArkData` preferences（持久化原始响应字符串），最后通过 `WeatherClient.fetch` + `WeatherParser.parse` 拉取并回写；坐标以当日首站四舍五入到 0.1° 后拼接 `lat,lon,date` 作为 key，避免把实时精确定位发给第三方。
- `WeatherAdvisor.ets`：纯策略层，把 WMO code 映射为中文标签，并按 `RAIN_MIN_PROB=60%`、`HEAT_MAX_C=33`、`COLD_MIN_C=0` 等常量生成人类可读简报与首个超阈值降水时段。
- `TripSignals.ets`：信号编排器，接收 `SignalContext`（isToday / nowMin / fix / checkedIds / currentKey / weather），按优先级产出 `off_route → behind → rain` 单条 `TripSuggestion`；当前节点由调用方（屏 15）统一判定传入，避免内部重复计算导致 hero 按钮与建议条目标不一致。
依赖方向单向：`TripSignals` 依赖 `WeatherAdvisor` 与 `SkipPlanner`；`WeatherStore` 依赖底层 `WeatherClient`/`WeatherParser`/`Geo`/`DateUtils`；三者均不触碰 UI 或 @kit 业务能力，仅 `WeatherStore` 直接持有 `preferences` 与 `common.Context`。
