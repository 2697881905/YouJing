本模块由三个并列的数据访问类组成，均通过静态方法暴露能力，无实例化：
- AccountStore.ets：单点登录态管理器，使用 ArkTS `preferences` 持久化 UnionID，结合 `@kit.AccountKit` 的 `HuaweiIDProvider` 执行静默登录；维护内存快照 `current`、`lastIdToken`，并通过 `AppStorage.setOrCreate(AUTH_STATE_KEY, ...)` 广播登录态给 UI 闸门；登出/登录时联动 `EntitlementStore.clear()` 清理权益缓存。
- ProfileStore.ets：用户资料的唯一出口，以 `profile_data_${uid}` 为 key 在 preferences 中整存 JSON 串；定义 `UserProfileData` 接口并声明与有据 `User` 同形，预留未来服务端共享字段；通过 `PROFILE_TICK_KEY` 广播刷新资料区；头像渲染走 `AvatarSpec` 联合类型（kind='symbol' | 'image'），当前恒返回符号占位。
- BadgeDao.ets：纯读侧 DAO，复用现有 RDB 表（checkin / activity / trip），用 JOIN + `c.trip_id || ':' || c.activity_id` 派生 id，不新建 badge 表；按 `AccountStore.uid()` 分区，输出 `BadgeBoard.BadgeRecord` 供上层合并。
依赖方向：BadgeDao → AccountStore；ProfileStore → AccountStore；三者共同依赖 `common/config/AccountConfig`、`common/logger/Logger` 与 `@kit.ArkData`。
