模块由三个职责清晰的文件组成：
- `CompanionEngine.ets`：纯静态类引擎，无 UI 依赖，对外暴露 `unplannedArrival` / `detectUnplanned` / `matchUnplannedSpot` / `moveToTomorrow` 等纯函数，输入 Trip/GeoPoint，输出 `CompanionPrompt | null`；通过 `nextStop` 判断是否挤占下一站，按「未知地点轻问」或「已识别挤占三选项」两条分支生成 Prompt。
- `CompanionStore.ets`：基于 `AppStorage` 的全局单点，以 JSON 字符串缓存提示（规避复杂嵌套对象 @StorageProp 刷新问题），并提供 `show/dismiss/current` 以及 `registerExecutor/execute/queueAction/takePendingAction` 执行器委托——当用户不在行程页时暂存 `CompanionAction`，待 OnTrip 挂载后取走执行，避免静默空操作。
- 类型与偏好：同目录下的 `CompanionTypes`、`CompanionPrefs` 被两个文件共享，构成引擎→存储→集成层的单向契约。
依赖方向：引擎仅依赖 `model/Trip`、`utils/DateUtils`、`utils/Geo` 和 `CompanionPrefs`，不感知任何 ArkUI 组件；UI 侧只消费 `CompanionStore.current()` 并注册 executor 回调。
