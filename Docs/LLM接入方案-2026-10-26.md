## 一、现状：生成管线已全通，唯一缺口是「真模型」

主链形态（真机已完整跑通，当前走 mock 传输）：

```
PromptBuilder.buildRequest（系统提示内嵌完整 JSON Schema，第一层防线）
  → LlmTransport.complete()
  → TripParser.parseTrip() 逐字段类型守卫（第三层防线）
  → Trip → TripDao.saveTrip 落库 → 屏8 渲染
  失败重试 1 次 → 仍失败抛 TRIP_GENERATE_RETRY_EXHAUSTED → 屏7 降级
```

传输层有两个实现（`ai/LlmClient.ets`），由 `MockConfig.USE_MOCK_DATA` 在
`LlmClient.generateTrip` 里二选一：

| 实现 | 状态 | 说明 |
|---|---|---|
| `MockLlmTransport` | **当前默认**（`USE_MOCK_DATA=true`） | 按请求参数确定性合成合法 Trip JSON，走完整「响应→守卫→Trip」链路，管线等价性已验证；但内容是合成的，`overview.summary` 带「离线合成」字样 |
| `HttpLlmTransport` | 骨架就绪、未接通 | OpenAI 兼容 chat/completions 形态；已实现 `response_format: json_schema {strict:true}`（§4.3 第二层防线，schema 与另两层同源 `TripSchema.TRIP_JSON_SCHEMA`）；端点取 `ApiConfig` 单点，两值为空即抛 `LLM_UNAVAILABLE`——失败路径真机实测过（§4c：屏7 显示「LLM 端点未配置」+ 两条修法可跳转） |

### HttpLlmTransport 接通前必须补的三件事

1. **鉴权头**：~~现请求头只有 `Content-Type`，没有 `Authorization` / API-Key 的注入点~~ →
   **已落 2026-10-26**：`Authorization: Bearer` 从 `ApiConfig.API_KEY` 注入，空 Key 只告警不阻断（兼容免鉴权本地网关）。
2. **Key 管理**：文件头注释承诺「Key 走 HUKS」，但 HUKS 代码尚不存在 →
   **开发期口径已定**：Key 填在 `ApiConfig.API_KEY`，文件级 `skip-worktree` 防误提交（与签名配置同一套口径）；
   **上架前仍需迁进系统凭据存储**，本条保持未完成。
3. **超时参数**：`http.createHttp().request()` 未设 `connectTimeout` / `readTimeout` →
   **已落 2026-10-26**：连接 10s / 读取 120s 走 ApiConfig 单点；真超时（平台码 2300025，libcurl 28）报
   `NETWORK_TIMEOUT`（屏7 文案「网络不通或超时」已就位），其余仍按「请求失败」报——延续「不按 message 猜超时」的老口径。

### 相关现状的两点更正 / 说明

- **小艺 Skill 平台侧已不是缺口**：2026-10-23 已按「仅自己使用」上架 `1.0.0`（`Docs/小艺Skill接入清单.md` §F 全部打勾，控制台状态「已上架」）。早前文档里「平台侧待用户操作」的表述以该清单为准。

### 第二层「AI 精选」仍是确定性替身

§3.3 的三层分层中，第二层（AI 帮用户勾选/排序）当前由 App 端规则承担：景点每组取热度 top-N（`SpotPickPage`），住宿区域按与所选景点的平均直线距离排序取前 3（`StayPickPage.rankByDistance`）。链路形态与文档一致，接真 LLM 后按文档把这一步换成独立精选调用即可。

## 二、两条路线对比（等用户拍板）

| 维度 | 路线 A：小艺开放平台「LLM 模式」Agent | 路线 B：直连 LLM HTTP API |
|---|---|---|
| 成本 | 平台承担算力（开发文档 §2.4 推荐理由） | 自担，按 token 计费；Prompt 内嵌完整 Schema + 精简景点列表，单次请求量可观（`MockTransport` 日志已打 system/user 字节数，可先估算） |
| 前置 | 平台控制台创建 LLM 模式 Agent + 工作流编排；**接入协议需先调研**（`ApiConfig` 注释「待调研」即指此事），公开资料有限 | 用户定三件事：服务选型、端点 URL、API Key 来源与预算 |
| 工作量 | 不可控（依赖平台调研 + 审核 1–3 个工作日 + 协议适配） | 一天级：补 §一 的三件事 + 翻开关 |
| 风险 | 平台协议/配额不受控；审核延迟（§8 已列风险） | Key 的端侧管理责任（HUKS 防落盘明文，防不了已 root 环境）；国内网络与合规选型 |
| 与现有代码的关系 | 新增第三个 `LlmTransport` 实现，传输抽象已就位 | 用现成的 `HttpLlmTransport` |

**不互斥**：传输层是接口化的，A、B 可以并存（B 先行验证规划质量，A 接入后按账号/网络环境选择）。若目标是尽快让真实模型进主链验证，建议先 B；A 作为降本路线并行调研。

### 路线 C：AGC 云函数代理（2026-10-26 增补，源自《实况窗方案》定稿）

《实况窗方案》（`7b259f1`）§1 已定调：**「原纯本地无后端」作废，AGC 云函数持有 LLM Key，
Key 不进客户端**；`replanDay` 云函数上游 LLM 超时 5s、端侧预算 8s（连接 2s + 读取 6s）、
`x-youjing-token` 鉴权、任何失败一律本地兜底。这对本文有三点直接影响：

1. **决策点 3（Key 录入）实质已被回答**：生产 Key 走云函数环境变量，不落端侧。
   `ApiConfig.API_KEY` 降级为**直连调试位**（开发期对拍用），上架前不再是必迁 HUKS 的负担。
2. **同一云函数形态可复用到主链生成**：`HttpLlmTransport` 的端点指向云函数 HTTP 触发器、
   鉴权头换/并成 `x-youjing-token`，即可成为「路线 B 的托管版」——Key 在云端、端侧零密钥。
3. **超时预算必须分档**：重排决策 8s；整程生成按附录 A 的体量（输出 ~1.5k token）
   需要 60–120s。一个函数承载两种用途时，要么拆两个函数，要么按 `schemaVersion`/路径
   分档超时——端侧 `READ_TIMEOUT_MS=120s` 只适用于生成档。

**三路线速览**：A（小艺平台）= 平台承担成本、协议待调研；B（直连）= 最快验证、Key 在端侧；
C（云函数）= Key 在云端、多一跳延迟与服务端运维，且基础设施已因《实况窗方案》在建设。
C 并不排斥 B：`HttpLlmTransport` 一套实现，端点指向谁就是哪条路线。

## 附录 A · Prompt 体量与单次成本测算（2026-10-26）

**方法**：静态复现，非运行时实测——`TripSchema.buildSchema()` 逐键同序复现 + `JSON.stringify`
同款紧凑序列化（Schema 常量因此是**精确值**）；`systemPrompt` 十条规则逐行复刻；`userPrompt`
用真实种子数据拼装（北京 12 站典型场景 + 王府井-东城核心）。响应样本按 `MockLlmTransport`
合成器同形态构造（3 天 12 站 6 餐）。**PromptBuilder / TripSchema 或提示词规则再改动后本附录即过时**；
真机复核口径：`MockLlmTransport.complete` 的日志 `system=…B user=…B` 打的是字符串长度
（UTF-16 单位 = 字符数），与下表「字符」列直接可比，接真端点后跑一次即校准。

| 段 | 字符 | UTF-8 | token 估算* |
|---|---|---|---|
| system（固定：10 条规则 + Schema 2,424 字符） | 3,235 | 3,975 B | 836–1,239 |
| user（12 站典型） | 963 | 1,893 B | 357–580 |
| user（4 站下限） | 473 | 957 B | 179–292 |
| **输入合计（12 站典型）** | 4,199 | 5,869 B | **1,193–1,819** |
| 输出（响应样本：3 天 12 站） | 4,411 | 5,575 B | 1,188–1,784 |

\* token 换算假设：ASCII ≈ 3.2–4.5 字符/token，中文 ≈ 0.6–1.05 token/字（不同分词器差异可达 ±30%）；
非精确值，选型后以真实 tokenizer 计数为准。每多选 1 个景点，user 段约增 70 字符。

**成本量级**（示意单价：输入 ¥4 / 输出 ¥12 每百万 token，以实际选型为准）：
单次生成 ≈ **¥0.02**（输入 ~1.5k + 输出 ~1.5k token）；重试最坏 ×2、日常一次规划 1–2 次调用，
仍在 **几分钱** 量级。**结论：成本不是路线 B 的决策瓶颈**——选型真正要权衡的是规划质量、
首字延迟（120s 读超时内的整包返回）与数据合规；预算一项可以放心批。
