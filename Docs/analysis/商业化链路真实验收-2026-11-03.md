## 一、一句话定位

**有径是一款「本地优先」的鸿蒙旅行规划 App。它的 AI 不是聊天框，而是一条从「用户说一句话」到「用户真的按这份行程走完一天」的完整闭环。**

三句话讲清差异：

1. **AI 只做决策，不做算术。** 时间、距离、动线、预算全部由端侧确定性引擎计算，LLM 只负责它真正擅长的语义判断（理解意图、排序、给理由）。
2. **AI 永远有兜底。** 每一处 AI 调用失败都会静默回落到本地规则引擎，用户永远不看到空屏或报错墙——这是普通 AI App 做不到的工程深度。
3. **AI 输出必须过闸。** 提示词内嵌 Schema → 结构化输出约束 → 服务端校验 → 端侧逐字段类型守卫，四道闸拦截模型幻觉，杜绝「AI 编一个酒店名写进你的日历」。

### 能力 1 · 一句话成行程（自然语言理解）— 行前 · 端侧 · 零 LLM 零成本

用户输入「下周三去北京玩三天，两个人，人均 2000，想吃小吃」，App 直接解析出目的地 / 出发日 / 天数 / 人数 / 预算 / 偏好 / 兴趣标签。

| 项 | 内容 |
|---|---|
| 核心代码 | `entry/src/main/ets/utils/TripIntentParser.ets:48` `TripIntentParser.parse()` |
| 预算折算 | `utils/TripIntentParser.ets:93` `budgetPerPerson()` — 总预算自动折人均并对齐滑杆档位 |
| 自动预选 | `utils/PlanAutoPick.ets:30` `PlanAutoPick` — 选点、住宿区、单日装填预算 |
| 关键设计 | 目的地识别用「动词优先」：动词后的城市才算目的地，「从北京去西安」判西安不判北京 |
| 歧义处理 | 每条推断都产出 `notes[]`，在确认面板逐条说明，不静默猜测 |

> **商业价值：** 这是**免费档的护城河**。用户第一句话就能得到结果，但这一段完全不需要任何模型调用——意味着免费用户可以无限使用，服务端成本为零。AI 能力不只在付费点，也在免费的获客入口。

### 能力 2 · LLM 行程生成 — 行前 · 云端 · 付费核心

给定已选景点 + 住宿区 + 风格 / 档位 / 交通 / 节奏，LLM 排出每天的时间轴、活动、餐次、交通段、理由与风险提示。

| 项 | 内容 |
|---|---|
| 提示词 SOT | `entry/src/main/ets/ai/PromptBuilder.ets:51` `systemPrompt()` — **20 条编号规则**（不是一段模糊提示词） |
| JSON Schema | `entry/src/main/ets/ai/TripSchema.ets:15` — Schema / 接口 / 守卫**物理同源**，改枚举只改这一处 |
| 端侧守卫 | `entry/src/main/ets/ai/TripParser.ets:38` `parseTrip()` — 逐字段类型 / 枚举 / 时序校验 |
| 编排与重试 | `entry/src/main/ets/ai/LlmClient.ets:354` `generateTrip()` — 失败重试一次，401 自动重新激活设备 |
| 服务端代理 | `bff/src/services/llm.js:35` `proxyLlmRequest()` — Key 注入、超时、429 透传、token 用量记账 |
| 服务端校验 | `bff/src/prompt/trip-validator.js:140` `validateTrip()` — Schema 驱动 + 语义约束 |

**提示词不是模板，是一份可回归的业务规格。** 20 条规则每一条都对应一次真机事故，且带日期与实测证据：

| 11 | 模型在中文里用英文双引号强调 → 整段 JSON 语法不合法 | 直连实测 2026-10-27 |
| 12 | 模型把景点地址整段重写（库里本来就有）→ 白烧 token 且写错 | 直连实测 2026-10-27 |
| 13 | 首日整个 `meals` 键被省略 → 守卫报错 → 重试让账单翻倍 | 真机实测 2026-10-27 |
| 17/19 | 模型排出 655 分钟的「一天」 | 真模型实测 2026-11-03 |

### 能力 3 · AI 精选（候选排序 + 一句理由）— 行前 · 云端 · 不扣额度

把候选景点池交给 AI，AI 排出优先级并给每站一句「为什么推荐给你」。

| 项 | 内容 |
|---|---|
| 端侧客户端 | `entry/src/main/ets/ai/PickClient.ets:24` `PickClient.pickSpots()` |
| 提示词 | `entry/src/main/ets/ai/PromptBuilder.ets:164` `pickSystemPrompt()` — 5 条规则，**强制不得编造候选里没有的事实** |
| 服务端 | `bff/src/routes/pick.js` → `bff/src/services/pickGuard.js:65` `guardPick()` |
| 云函数 | `cloud/pickSpots/index.js`（AGC 零自购服务器方案） |

**三通路优先级：** AGC 云函数 → 端侧直连 → BFF → 确定性规则兜底。**任何失败一律返回 null**，页面保留原热度排序，不空屏。

> **商业价值：** 这是「AI 帮用户做选择」的最短变现路径——用户看到 AI 推荐理由后，转化到付费生成的意愿显著高于看到冷冰冰的列表。

### 能力 4 · 行中对话式重排（意图理解）— 行中 · 云端 · 付费

用户在行程当天对 App 说「我累了，今天剩下的就都别去了」，App 理解并预演改动，确认后才落库。

| 项 | 内容 |
|---|---|
| 意图提示 | `entry/src/main/ets/ai/ReplanPromptBuilder.ets:189` `intentMessages()` |
| 四种动作 | `skip` / `shift`（顺延）/ `add`（加一站）/ `replace`（换站） |
| 决策守卫 | `entry/src/main/ets/ai/ReplanParser.ets:18` `parseDecision()` |
| 时间算术 | `entry/src/main/ets/data/SkipPlanner.ets:197` `plan()` — **全部留在端侧**，可离线断言 |
| 云函数 | `cloud/replanDay/index.js` |
| 端侧直连 | `entry/src/main/ets/ai/ReplanClient.ets:24` — 云函数未部署时也能跑真 LLM |

**关键的职责切分：** LLM 只输出「保留谁、每站停多久、空档放哪」；**具体时刻由端侧确定性引擎算**。这让 AI 的输出永远不可能造成时间轴错乱。

**本地查询优先于联网：** 「时间够吗」走本地时间预算、「附近有啥吃的」走 Map Kit 附近检索——**这两类意图不花模型额度**（`pages/OnTripPage.ets:702` `prepareIntent()`）。

> **商业价值：** 对标主流地图 App 的「AI 行程助手」，但我们有别人没有的两点：**改行程必须用户确认**（预演 → 确认执行 → 可撤销），以及**AI 决策与时间算术物理分离**。

### 能力 5 · 伴随助手（主动感知 + 偏好学习）— 行中 · 端侧 · 零 LLM

旗舰差异化能力。助手**站在「现实」这边**：当计划与现实产生真实后果时，就地浮出一张「请示卡」，端出带默认推荐的可点选选项。

| 项 | 内容 |
|---|---|
| 核心引擎 | `entry/src/main/ets/companion/CompanionEngine.ets:26` `CompanionEngine` |
| 偏好学习 | `entry/src/main/ets/companion/CompanionPrefs.ets:14` `CompanionPrefs` |
| 状态总线 | `entry/src/main/ets/companion/CompanionStore.ets` — AppStorage 跨组件单点 |
| 能力 1 | **规划外到访检测**：停留 ≥3 分钟 + 落在计划外已知景点 → 判断是否挤占下一站 |
| 能力 2 | **请示而非打扰**：塞得下 → 静默吸收；挤占 → 三选项请示（挪明天 / 快逛一下 / 按原计划走） |
| 能力 3 | **偏好降级闭环**：同类低风险决定连续选推荐 ≥3 次 → 从「请示」降为「通知」；**纠正一次立刻回请示** |

**「助手站在现实这边」是产品哲学，也是技术选择：** 引擎只产出结构化意图（`CompanionPrompt`），**不直接改行程**；执行交给集成层接 `SkipPlanner`。大脑与手分离，所以引擎可离线断言、可单测。

> **商业价值：** 这是把「AI 功能」升级为「AI 伙伴」的一步。竞品要用户主动提问；我们**检测到现实冲突才开口，且越用越少打扰**——这是留存护城河。

## 四、技术壁垒：四道闸防幻觉

这是本项目**最值得在商业讲解中强调**的工程资产。

```
┌─ ① 提示词内嵌完整 JSON Schema（第一道）
│    ai/PromptBuilder.ets:51 + ai/TripSchema.ets:15
│
├─ ② 结构化输出约束（第二道）
│    response_format: {type:'json_schema', strict:true}
│    bff/src/prompt/contract.js:42 buildResponseFormat()
│
├─ ③ 服务端前置校验（第四道 · 提前拦截）
│    bff/src/prompt/trip-validator.js:140 validateTrip()
│    Schema 驱动 + 语义约束（天数、endTime>time、每日午晚餐各一条）
│
└─ ④ 端侧逐字段类型守卫（第三道）
     ai/TripParser.ets:38 parseTrip() → 299 行 ArkTS 类型守卫
     任一字段不合规抛 AppError(2xxx) 并带精确字段路径
```

**Schema / 接口 / 守卫三者物理同源**（都在 `ai/TripSchema.ets`）：改枚举只改这一处，端侧、提示词、服务端校验器同步生效，不存在「抄了三份」的漂移风险。BFF 侧由 `bff/scripts/sync-prompt-contract.mjs` 从端侧 SOT 同步生成物，**同步漏了会被测试哈希拦住**。

**模型输出还会在落库前被二次纠正**（`ai/LlmClient.ets:354`）：

- 行程主键重铸（防撞 id 删掉旧行程）
- 人数 / 预算 / 目的地以**用户输入为准**，不信模型自述（模型 echo 错会让预算错一倍）
- 剔除与餐次重复的 food 活动（防「两顿午饭」）
- 活动 id 按天序重铸（防 UNIQUE 撞键导致整趟保存回滚——而模型额度已扣）
- 总费用以各天合计为准（防费用页两个数打架）
- 地址 / 坐标 / 开放时间 / 预约**全部按景点库回填**

> **讲解话术：** 「市面上很多 AI 行程 App 会给你编一个根本不存在的酒店名字，然后写进你的日历。我们的 App 里，模型**没有资格**编造事实——它只被允许排序和给理由，所有事实都来自本地数据库。」

**取证约定：结论要能被复现。** UI 问题必须同机位实拍复拍；布局争议用 `uitest dumpLayout` 读真实 bounds；颜色争议用像素量化——**不接受「看代码应该没问题」**。

### 三条 AI 通路

```
MockLlmTransport   端侧规则引擎   零成本 · 离线可跑 · 免费档
   ↓ 失败 / 未配置
HttpLlmTransport    BFF 中转       Key 注入 · 扣额度 · 校验 · 记账 · 商业化
   ↓ 云函数未部署
DirectLlmTransport  端侧直连       开发期兜底 · 与 BFF 共用同一份 PromptBuilder
```

**三条通路共用同一份 `PromptBuilder` SOT**，所以切换通路不改变任何业务规则——这是「架构为商业化服务」的体现。

## 九、3 分钟讲解脚本

**第 1 段 —— 定位**
> 「有径是鸿蒙上的旅行规划 App。差异化不是聊天框，是一条闭环：**说一句话 → 出行程 → 按真实位置走完 → 回来看见自己走过的路**。」

**第 2 段 —— AI 与确定性如何分工**
> 「这里有个关键设计：**AI 只做决策，不做算术**。时间、距离、动线、预算全由本地确定性引擎算，模型只负责它真正擅长的语义判断。这带来两个商业结果——**免费用户无限用不烧钱**，以及**AI 出错也不会让行程错乱**。」

**第 3 段 —— 防幻觉四道闸**
> 「大模型会编造。我们的对策是四道闸：提示词内嵌完整 Schema、结构化输出约束、服务端校验、端侧逐字段类型守卫。而且 Schema、接口、守卫**物理同源**——改枚举只改一处。
> 举个真实的例子：模型曾经编出一个根本不存在的酒店名，那个名字会被写进用户的日历。现在模型**没有资格**编造事实——地址、坐标、开放时间、预约信息全部按本地景点库回填，模型只被允许排序和给理由。」

**第 4 段 —— 差异化的两个点**
> 「第一个点：我们的**伴随助手**站在现实这边。你去了计划外的地方，它检测到会挤占下一站，就浮出一张请示卡——挪明天、快逛一下、按原计划走，三个选项带默认推荐。而且你连续三次选推荐，它以后只通知不问；你纠正一次，立刻恢复请示。
> 第二个点：行中的对话式重排，**LLM 只说保留谁、每站停多久，具体时刻本地算**。改行程必须用户确认，预演 → 确认 → 可撤销。」

**第 5 段 —— 商业化**
> 「免费档跑本机规则引擎，零 token 成本；真模型一次约五分钱。定价三档：免费、9.9 元单行程通行证、19.9 月 / 98 年订阅。云端只看到随机 UUID，行程内容永不上传。」

**收尾 —— 信任**
> 「最后说一句工程文化：这个项目有 24 个静态审计脚本、8 个离线断言脚本、一条真进程商业探针。我们的原则是**结论要能被复现**——不接受『看代码应该没问题』。」
