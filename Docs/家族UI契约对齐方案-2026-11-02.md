> 状态：2026-11-02 设计待评审，未实施，未写一行 UI 代码。
> 触发：用户要求「全量 UI 优化 + 开发推进；作为与『有据』同系列作品，布局、排版、组件设计与有据统一」。

## 0. 口径：谁是真值源

问「不一致时以哪侧为准」时用户未答，我按契约文本代拍，写在这里供推翻。

**裁判是 `~/Pictures/有径/有径-设计底稿-v1/docs/DESIGN.md` 本身，不是「有据的实现」。** 三条原文依据：

| DESIGN.md 行 | 原文要义 |
| --- | --- |
| 3 / 644 | `name: youju-family-design-language`；「这是**有据产品家族**唯一的设计契约；除显式点名某产品的段落外，**文件里每个值都是共享的**」 |
| 655 | 「产品层可以**新增**组件、色板、几何，但**永远不许重调一个 family token**；缺值就从本文推导，不要发明」 |
| 1167-1168 | 「不要按产品 fork 共享 token 值；若有据需要新的表面档位，有径继承它」「不要让某个 App 发明第三块玻璃、第三档圆角、第二套 display 字族」 |

所以「与有据统一」的正确含义 = **两个 App 都回到同一份契约**。有据偏离契约的地方不抄（§4 只登记）。这个口径还有两条好处：不需要改动 DESIGN.md（用户规矩：不许为过闸门改权威契约），也不需要推翻有径已真机验收的深色栏带与对比度结论。

## 3. 分层设计

### 3.1 Token 层（零像素变化）

1. `SpaceTokens` 新增语义字段，不改任何数值、不改存量名：
   `itemGap=12`、`blockGap=16`、`sectionGap=24`、`pagePadding=16`、`pagePaddingWide=20`、`gridGutter=12`。
   六个名字直接取自契约 `layout.*` 的 `item-gap`/`block-gap`/`section-gap`/`page-padding`/`page-padding-wide`/`grid-gutter`，六个值全部是已有档位，不产生新数字。
   为什么不重命名 `md`/`lg`/`xl`：那要机械改动 100 多个触点，而且极易在「有径 `md`=12 而契约 `md`=20」这种语义错位上二次翻车。改名的好处由新增语义名拿到，旧名原地不动。
   语义名的采用靠代码评审与迁移过程，不靠尺——静态尺无法判断「这一处 `.padding(SpaceTokens.lg)` 是不是页面内缩」，所以本文不承诺这种规则；尺只管 §5 里 R1-R6 那些可机判的事。
2. 删除零消费方的 `lgLoose=18` 与 `threeXl=28`，同步从 `ALLOWED_SPACINGS` 去掉。依据：18 在契约里只作为 `tab_side_margin`/`tab_bottom_gap` 的具名布局值存在，有径没有这两处；28 在契约里是圆角档，不是间距档。
3. `MotionTokens` 定稿为契约命名的五档，删掉无消费者的 `durationFast=100`：
   `press=140`、`pressScale=0.97`、`control=220`（原 `durationBase=200`，改值又改名）、`container=320`（原 `durationSlow=300`）、`shimmer=1200`（`FamilySkeleton` 需要）。
   因为全 App 今天零动画（§2），这次改值**没有任何用户可见影响**，纯属拆掉「第二套语言」；将来第一次用动画时只会用上这五个名字。
   契约其余 12 项（`page-enter 420`、`emphasis 460`、`stagger 40`、`shared-element 380`、`path-draw 460`、`reveal-offset 8`、`segmented-press-scale 0.94`、`press-opacity 0.92`，以及 `decelerate`/`emphasized`/`spring`/`spring-soft` 四条曲线）**一律不加**：没有消费方的声明就是死字段，「不许发明」与「不许囤积」是同一把尺。真要做转场，随动效切片一起补。
   `curveStandard` 从 `Curve.EaseInOut` 换成契约的 `cubic-bezier(0.2, 0.8, 0.2, 1)`：A1 内先做单点可行性实验再决定。ArkTS 的 `Curve` 是枚举，自定义贝塞尔要用 `@ohos.curves.cubicBezierCurve()` 返回 `ICurve`，而 `.curve()` 能否接受 `ICurve` 本机未证实。验证通过则换；不通过则保留 `EaseInOut`，把这条写进 §7 当平台量纲边界，不许凭感觉改。
4. 新增 `design/ElevationMode.ets`：`Elevation.card()` / `Elevation.floating()` / `Elevation.segmented()`，内部唯一一处读 `isDarkMode`，返回归零值或对应 `ShadowTokens`。现有 8 处页面分支全部改为调用它，页面里不再出现 `isDark`。

### 3.2 组件层（建 5 件，先不挂载，零像素变化）

契约点名的家族件里，**只有消费方 ≥2 处才建件**（契约允许产品层加件，没允许造没人用的抽象）：

| 建不建 | 契约来源 | 规格（逐字来自 DESIGN.md） | 现存消费方 |
| --- | --- | --- | --- |
| 建 `FamilyCard` | 333-340 | 圆角 20、底 `surfaceElevated`、padding 16、innerGap 12、`elevation.card` | **15 处**：card 圆角 + `surfaceElevated` 底共 17 处，扣掉 2 个 `@CustomDialog`（属 `sheet-modal`，padding 20 已合规）；其中 8 处全达标，7 处只差把 padding 改成 16 |
| 建 `FamilyPanel` | 产品层新增件 | 圆角 14（契约 `rounded.md`）、底 `surfacePanel`/`surfaceSubtle`/`canvas`、padding 12（契约 `sm`） | 其余非 elevated 容器 14 处 |
| 建 `FamilySeparator` | 378-380 | 高 0.5（`hairlineWidth`）、色 `separator`，唯一实现 | 12 处 / 6 种写法 |
| 建 `FamilyEmptyState` | 395-399 | `canvas` 底、文案 `callout`(14/400/20) + `muted`、图标 `faint` | 13 个文件的现写空态 |
| 建 `FamilySkeleton` | 390-394 | `skeletonBase`/`skeletonHighlight`、圆角 14、shimmer 1200ms | 生成页局部 builder |
| **不建** | 381-384 `avatar`；328-332 `icon-button`；385-389 `badge-dot` | 契约值原样登记，不实现 | 分别 1 处（`MinePage`）、0 处（顶栏圆钮是 HDS 官方件）、0 处 |

`FamilyCard` 刻意**无 props**（不接受自定义 padding 或底色）：一开口，46 处漂移就会重新长回来。确需别的规格即说明它不是 card，归 `FamilyPanel`、`sheet-modal` 或媒体族。

### 3.3 迁移层（唯一会变像素的部分）

分类判据按**同链底色**分派，46 个节点一个不剩：

| 去向 | 判据 | 处数 | 像素变化 |
| --- | --- | --- | --- |
| `FamilyCard` | 底 = `surfaceElevated` 且不是 Dialog | 15（8 已达标 + 7 改 padding 12→16） | 7 处每侧 +4vp |
| `sheet-modal` | 两个 `@CustomDialog`：padding 20 + 圆角 20 | 2 | 无（只换件） |
| 行级高亮，不是容器 | 底为条件表达式 4 处（`focusActId`、`dragIdx`、`selected`、`highlight`）+ 恒为强调色 `primaryTint` 1 处 | 5 | 圆角 20→14，色一律不动 |
| `FamilyPanel` | 底 = `canvas`/`surfaceSubtle`/`surfacePanel` | 14 | 圆角 20→14，padding 统一 12 |
| 逐个定夺 | 同链**无底色**（多为裁剪、图片、叠层壳） | 10 | 判为叠层壳就去掉圆角（视觉无变化）；判为媒体则改 `media`(6) |

合计 15+2+5+14+10 = 46 ✓。圆角 `hero`(28) 那 4 处不在此表内（它们不写 `RadiusTokens.card`），属契约 `activity-photo`/`card-media` 族，本轮保留。

本方案的可见像素改动共 **26 处**，只有这三类，其余全是等价换件：

1. 7 张真卡内边距统一成 16（现值 12 或 0）→ 内容每侧 +4vp、单卡高约 +8vp；
2. 14 处 `FamilyPanel` 圆角 20 → 14；
3. 5 处行级高亮圆角 20 → 14（底色不动）。

每处迁移必须：改 → 构建装机 → 同机位复拍（深、浅两档）→ 滚动净空尺与对比度尺仍过。逐页清单在实施计划里按 46 个 `文件:行号` 展开（附录命令可再生成）。
注意 §2 里「padding 12 共 22 处」是**跨类别**总数（含 Panel 与叠层壳），真正落到卡上的只有 7 处——这个区别就是必须先分类再动手的理由，否则会连带把 15 处本不该变 16 的容器一起撑大。

### 3.4 材质与实拍收口

- `HdsChrome.BAR_BLUR_RADIUS` **保持契约的 24**，不抄有据的 50；但本轮必须做一次真机实拍：截图量「24 在这台 Pocket 2 上到底出不出可见磨砂」。这条自留疑问从 2026-10-25 挂到今天，用户明确说过别再自行改动，所以只取证、不改值。若证据显示 24 出不了磨砂，就升级为设计取舍问题交用户拍。
- 地图页 dock 渐变遮罩、屏8 吸顶行等已验收项**不在迁移范围**。

## 5. 新一把尺：`tools/audit_family_card.py`

序号接现行清单，本文不自立编号：现行 = 14 把 `audit_*.py` + `verify_scroll_clearance.py`。为避免和 CHANGELOG 里「第四把尺（真机对比度）」「第 14 把尺（滚动净空）」两套叫法打架，新尺一律按文件名称呼。顺带记一条文档漂移：`README.md:23` 与 `:39` 仍写「十二把静态尺」，而 `README.md:74` 已是「十三把」——A1 一并校正。

静态、零依赖，六条规则；每条都要一条 `--selftest` 阳性样本，防止「0 命中假绿」这个本项目踩过的坑：

| 规则 | 判据 |
| --- | --- |
| R1 | `pages/` 内出现 `.borderRadius(RadiusTokens.card)` 即报——这是迁移完成的客观终点 |
| R2 | `components/` 内家族件的三元组必须逐字等于契约（20 / 16 / `surfaceElevated`），漂移即报 |
| R3 | `pages/` 内自写发丝线即报（`hairlineWidth` 出现在 `.border(`、`.height(`、`backgroundColor` 三种形态），要求走 `FamilySeparator` |
| R4 | 出现 `SpaceTokens.lgLoose`/`SpaceTokens.threeXl`，或 `ALLOWED_SPACINGS` 与契约 8 档不吻合，即报 |
| R5 | `.duration(` 后跟数字字面量即报（现 0 处，属防回归） |
| R6 | 页面出现 `isDarkMode` 即报，须走 `ElevationMode` |

上闸节奏：R4/R5/R6 在 A1 就上（当天可绿）；R3 在 A3 之后上；R1/R2 在 A5 之后上。这是「先有尺再迁移」的例外：R1 若第一天就生效，会把现存 46 处全报红，闸门失去可用性，所以按切片逐步收紧。

## 7. 边界与待办（不阻塞实施）

- **要不要动效层，需要你拍**：实测有径全 App 零动画（`.animation`/`animateTo`/`.transition` 各 0 处），而有据有 page-enter、共享元素、一镜到底、shimmer 一整套契约化动效。本方案默认**不做**（§8），因为动效是独立一片工程且必须真机逐屏验帧；但「看起来同源」在别的 App 上很大一部分来自动效，所以把它摆在这里而不是替你省掉。若要做，A6 之后单开子项目。

## 附录：本文数字的复算方式

`/tmp` 在本机重启即清空，所以历史计数不靠临时脚本存活。下面这段可整段粘进 `python3` 现场重算（2026-11-02 实测输出：46 个自写卡片节点、三元组达标 8 处、padding 为 `SpaceTokens.md` 18 处）；A1 之后这两个数由入库的 `tools/audit_family_card.py` 持续打印。

```python
import re, glob, collections
files = (glob.glob('entry/src/main/ets/pages/*.ets')
         + glob.glob('entry/src/main/ets/components/*.ets'))
pad = collections.Counter(); bg = collections.Counter(); n = tri = 0
for f in files:
    L = open(f, encoding='utf-8').read().split('\n')
    for i, l in enumerate(L):
        if '.borderRadius(RadiusTokens.card)' not in l:
            continue
        ind = len(l) - len(l.lstrip()); ch = []; j = i - 1
        while j >= 0 and L[j].strip():
            si = len(L[j]) - len(L[j].lstrip()); st = L[j].lstrip()
            if si > ind or (si == ind and st.startswith('.')):
                if si == ind: ch.append(st)
                j -= 1
            else: break
        ch = ch[::-1]; k = i + 1
        while k < len(L) and L[k].strip():
            si = len(L[k]) - len(L[k].lstrip()); st = L[k].lstrip()
            if si == ind and st.startswith('.'): ch.append(st); k += 1
            else: break
        c = ' '.join(ch); n += 1
        m = re.search(r'\.padding\(\{?\s*([^),}]*)', c); b = re.search(r'\.backgroundColor\(([^)]{1,30})', c)
        pad[m.group(1).strip()[:24] if m else '无'] += 1
        bg[b.group(1).strip()[:28] if b else '无'] += 1
        if m and m.group(1).strip() == 'SpaceTokens.lg' and 'surfaceElevated' in c: tri += 1
print(n, tri); print(pad.most_common()); print(bg.most_common())
```
